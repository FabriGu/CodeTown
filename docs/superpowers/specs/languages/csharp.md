## Scope

| | |
| --- | --- |
| `NAME`, `LABEL` | `"csharp"`, `"C#"` |
| `EXTENSIONS` | `.cs` |
| `GRAMMARS` | `.cs` → `csharp` (confirm the exact name; it may be `c_sharp`) |
| `SHEBANGS` | none |
| `CONFIG` | `*.csproj`, `Directory.Packages.props`, `Directory.Build.props` |
| `FIRE` | `True` (calibrate) |

The node types below are expected. Print a snippet's subtree to confirm each one, and follow
the grammar where it differs.

Read `.csproj` and `.props` files as XML with `xml.etree.ElementTree`:

- `PackageReference Include=…` names (and `Update=…` in central package management);
- `ProjectReference Include=…` paths;
- `RootNamespace`.

If a file doesn't parse, ignore it. Never run `dotnet`.

## Building grain

One building per file.

## Projects

Each tracked `.csproj` defines a project at its folder. A `.cs` file belongs to the project
with the deepest folder containing it. Files under no project belong to a project called `""`.

## Facts per file

- **Scope:** the file's namespace. That is a `file_scoped_namespace_declaration`, or the first
  `namespace_declaration` (whose blocks may be nested; join their names with `.`). `""` if none.
  For files with several namespace blocks, declarations take the scope of their own block.
- **Declares:** names of types declared directly in a namespace: `class_declaration`,
  `struct_declaration`, `interface_declaration`, `enum_declaration`, `record_declaration` and
  `delegate_declaration`. Each is a `(namespace, name)` pair. A file can declare into several.
- **Exports:** `public` types, plus the `public` members of `public` types: methods, properties,
  fields, events and constructors. `partial` types count once per file.
- **References:** `identifier` nodes used in type positions, base lists, object creation,
  attribute names (also try `Name` plus `Attribute`), and member-access receivers. Deduplicated
  and sorted.
- **Complexity:** 1, plus:
  - `if_statement`, `for_statement`, `foreach_statement`, `while_statement`, `do_statement`,
    `switch_section`, `switch_expression_arm`, `catch_clause` and `conditional_expression`;
  - `binary_expression` with `&&`, `||` or `??`.
- **Entry:** a `static` method named `Main`, or the file has top-level statements
  (`global_statement`).
- **Fire:** `langkit.first_error`.

## Imports

- `using A.B;`, `global using A.B;` and `using static A.B.C;` give `Import("A.B")`, or
  `Import("A.B.C")` for the static form.
- `using X = A.B.C;` gives `Import("A.B.C")`.
- Each distinct reference gives `Import(name, kind="reference")`. The resolver checks it
  against the namespaces in scope (next section), and each hit is one road.

## Resolution

Build a `SymbolIndex` of `(namespace, type name, path)`.

**Namespaces in scope**, for a file in namespace `A.B.C`:

1. its own namespace and every parent (`A.B.C`, `A.B`, `A`), which C# searches implicitly;
2. its `using` namespaces;
3. the `global using` namespaces of every file in the same project.

**Each reference** goes to the first namespace in that order where `lookup` hits, excluding
the file itself. Hits are roads.

**Partial types.** When `lookup` is ambiguous, and every declaring file marks the type
`partial`, use `lookup_all`: one road to each declaring file except the importer itself. Two
non-partial declarations of one name are still ambiguous, and reach nothing.

**A `using static A.B.C`** reaches the file declaring `C` in `A.B`. **A `using` alias** to a
type reaches its file.

**A `using` namespace that no repository file declares into:**

- **Framework:** `System`, `System.*`, `Microsoft.CSharp`, `Microsoft.VisualBasic` and
  `Microsoft.Win32`. No road and no warehouse.
- **External:** match the namespace against the project's `PackageReference` names by longest
  prefix (`Newtonsoft.Json.Linq` → `Newtonsoft.Json`). Otherwise use the first two segments
  (`Microsoft.Extensions.Logging` → `Microsoft.Extensions`).

## Tests

- A project is a test project if its `.csproj` references a package whose name contains `xunit`,
  `nunit`, `MSTest` or `Microsoft.NET.Test.Sdk`. Every `.cs` file in a test project is a test.
- Files named `*Tests.cs` or `*Test.cs` are also tests.
- Tests link through references, through core.

## Excluded (`is_excluded`)

- Anything under `obj/` or `bin/`.
- `*.g.cs`, `*.g.i.cs`, `*.Designer.cs`, `*.AssemblyInfo.cs` and `GlobalUsings.g.cs`.
- Files whose leading comment contains `<auto-generated`.

## Required tests

1. `src/App/Program.cs` (namespace `Acme.App`, `using Acme.Core;`, references `Parser`) reaches
   `src/Core/Parser.cs` (namespace `Acme.Core`).
2. A file in `Acme.App.Web` referencing `Settings` declared in `Acme.App` reaches it with no
   `using`, through the parent namespace.
3. A `global using Acme.Core;` in one file of a project lets another file in that project reach
   `Parser`. A file in a different project does not.
4. File-scoped namespaces (`namespace Acme.Core;`) and nested block namespaces both set scope
   correctly.
5. `using static Acme.Core.Guards;` reaches `Guards.cs`. `using P = Acme.Core.Parser;` reaches
   `Parser.cs`.
6. A file declaring two types in two namespaces is found under both.
7. `partial class Form`, declared in `Form.cs` and `Form.Layout.cs`: a third file referencing
   `Form` reaches both. Two non-partial `Dup` classes reach nothing.
8. `using System.Linq;` gives no warehouse. With `<PackageReference Include="Newtonsoft.Json" />`,
   `using Newtonsoft.Json.Linq;` gives warehouse `Newtonsoft.Json`.
9. The repository declares `AuditAttribute`, and `[Audit]` on a method reaches its file, through
   the `Attribute` suffix rule.
10. Exports: a public class with 2 public methods, 1 public property and 1 private method exports
    the class plus 3.
11. Complexity: a fixture with one of each construct has the exact value, switch expression
    included.
12. A `static void Main` file is an entry, and so is a `Program.cs` with top-level statements.
13. A project whose `.csproj` references `xunit` makes its files tests. Its test referencing
    `Parser` gives `Parser.cs` an annex.
14. `obj/Debug/X.g.cs`, `Form1.Designer.cs` and an `<auto-generated>` file are not buildings.
15. A file with a syntax error is on fire.

## Calibration

[serilog/serilog](https://github.com/serilog/serilog): several projects, a test project, global
usings. Report the usual note, plus the share of references that resolved.

## After calibration

- Test projects come from `.csproj` through core's `test_files` hook, so every file of an xunit,
  NUnit or MSTest project is a test. Name and attribute markers remain as the fallback.
- A file in a library project (not a test project, `OutputType` not `Exe` or `WinExe`) that
  declares a top-level `public` type is `public`, so a library's API is never abandoned
  (serilog: abandoned went from 30 to 5).
- Grammar errors inside `#if` and `#else` branches are suppressed; other syntax errors burn.

## Known limits

- Extension methods resolve only when their static class is referenced by name.
- `ProjectReference` is read but not enforced: any project's types are reachable.
